# Current project vs. latest official Laravel Livewire starter kit

Research date: 2026-08-27

## Baseline

This comparison uses the official `laravel/livewire-starter-kit` `main` branch at commit [`dbf60cf451f5a518f130b4ee16febade2dc21722`](https://github.com/laravel/livewire-starter-kit/tree/dbf60cf451f5a518f130b4ee16febade2dc21722) (2026-08-24), rather than its old `v1.0.1` release. The official README now describes that branch as Livewire 4, TypeScript, Tailwind, and Flux UI, while Laravel's starter-kit page describes authentication, settings, configurable layouts, CI, Tailwind 4, and light/dark modes as the current product defaults ([README](https://github.com/laravel/livewire-starter-kit/blob/dbf60cf451f5a518f130b4ee16febade2dc21722/README.md), [official starter-kit page](https://laravel.com/starter-kits)).

Important qualification: `main` is a configurable source template. Its `@chisel-*` regions and `install:features` command mean registration, email verification, password confirmation, two-factor authentication, and passkeys can be selected or removed when a new app is generated. They should not all be treated as mandatory Laravel 13 upgrade work ([composer manifest](https://github.com/laravel/livewire-starter-kit/blob/dbf60cf451f5a518f130b4ee16febade2dc21722/composer.json), [feature installer](https://github.com/laravel/livewire-starter-kit/blob/dbf60cf451f5a518f130b4ee16febade2dc21722/app/Console/Commands/InstallFeaturesCommand.php)).

The current project snapshot is commit [`09de9bd6dbb4e7e4e7836e0030912fbf9c8309d3`](https://github.com/braun-bauen/search-my-audio/tree/09de9bd6dbb4e7e4e7836e0030912fbf9c8309d3).

## Authentication and UI feature delta

The current kit can generate capabilities this project does not have: Fortify-managed two-factor authentication, WebAuthn passkeys, recovery codes, a security settings screen, and a `/.well-known/passkey-endpoints` response. Its route template also moves appearance and security behind both `auth` and `verified`, whereas this project permits authenticated users to reach all settings pages and keeps password management as a separate page. These are user-facing behavior and information-architecture changes, not neutral modernization defaults ([latest settings routes](https://github.com/laravel/livewire-starter-kit/blob/dbf60cf451f5a518f130b4ee16febade2dc21722/routes/settings.php), [latest security page](https://github.com/laravel/livewire-starter-kit/blob/dbf60cf451f5a518f130b4ee16febade2dc21722/resources/views/pages/settings/security.blade.php), [current routes](https://github.com/braun-bauen/search-my-audio/blob/09de9bd6dbb4e7e4e7836e0030912fbf9c8309d3/routes/web.php)).

Conversely, the project has substantial behavior absent from the generic starter kit: subscription checkout and billing portal routes, Stripe webhooks, subscribed-only history, audio search/upload/results/history pages, S3/R2 storage, queued processing, reports/email, Sentry, and Resend. A skeleton rebase would require transplanting and revalidating all of these integrations; the starter kit provides no replacement for them ([current routes](https://github.com/braun-bauen/search-my-audio/blob/09de9bd6dbb4e7e4e7836e0030912fbf9c8309d3/routes/web.php), [current manifest](https://github.com/braun-bauen/search-my-audio/blob/09de9bd6dbb4e7e4e7836e0030912fbf9c8309d3/composer.json)).

## Recommendation

Do **not** refresh the project from the newest starter-kit skeleton. Upgrade in place and use the current kit as a checklist.

Adopt as part of the compatibility migration:

1. PHP 8.3+, Laravel 13, Tinker 3, Livewire 4, and a current Flux 2 minor.
2. Native Livewire single-file components and `Route::livewire`, removing Volt only after equivalent routes/components pass regression tests.
3. Relevant Laravel 13 framework config deltas merged individually.
4. Current dependency/tool versions where compatible; the project is already on Vite 8, Tailwind 4, and Laravel Vite Plugin 3.

Consider separately after parity:

1. Larastan level 7 and consolidated Composer quality scripts.
2. Immutable dates and destructive-command protection; evaluate the stricter password policy with product/security intent.
3. Blaze, gated by measured benefit and regression testing.
4. Fortify, 2FA, and passkeys as a dedicated authentication/product change.

Explicitly preserve:

1. Existing layouts, markup, emerald/slate theme, custom CSS utilities, route names, and settings information architecture.
2. Pest unless the team independently wants a PHPUnit migration.
3. Flux Pro and application packages/integrations actually in use.
4. Stripe CSRF handling, Cashier behavior, billing/search/storage/queue/mail/observability configuration, and current domain model behavior.

In short, the latest frontend toolchain is already close to this project. The meaningful gap is Laravel 13 + Livewire 4's component/auth/quality conventions. Those defaults are best cherry-picked; regenerating the starter kit would introduce an avoidable UI and authentication rewrite.
